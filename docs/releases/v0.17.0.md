# v0.17.0 — HTML to PNG and SVG to PNG

The plugin now creates images three ways: ComfyUI diffusion, HTML rendering and SVG rasterization.

## Added

- `render_html` — renders a document to PNG with a Chromium-family browser. Accepts inline HTML, a workspace file, or a built-in template plus slot values.
- `render_svg` — rasterizes SVG at any size; defaults to the SVG's own width/height or viewBox.
- `list_render_templates` — the template catalog with ids, canvas sizes and slot names.
- Six brand templates: `og-card`, `social-square`, `banner`, `feature-grid`, `stat-card`, `comparison`.
- **Studio → Render** surface: template picker, code editor, slot fields, size/scale/background, preview and a session result rail.
- Settings card section: browser path, default canvas, background, save-source toggle, and a renderer health line.
- Sora and JetBrains Mono ship with the package so rendered text matches the brand.
- Two skills: `html-to-png` and `svg-to-png`.

## How it works

A render writes a temporary page and runs the installed browser with `--headless=new --screenshot` at an exact viewport and device scale factor; the PNG then goes through the same attach → workspace-save → gallery path as a generated image. No native dependency is added: the browser is the renderer.

Renders are sandboxed by construction. Markup is sanitized (script/iframe/object removed, inline handlers stripped, remote URLs blanked), the page carries a `default-src 'none'` CSP, and DNS resolves to nothing for the duration.

One switch was deliberately left out: `--blink-settings=scriptEnabled=false` makes Edge exit 0 while writing no screenshot at all. Scripts are already blocked by CSP and the sanitizer, so the switch was not worth the silent failure.

## Limitations

- A Chromium-family browser must exist on the machine; the settings card reports when none is found.
- The canvas is explicit — no auto-height or full-page capture yet.
- No JavaScript, no network, no external fonts in rendered pages.
