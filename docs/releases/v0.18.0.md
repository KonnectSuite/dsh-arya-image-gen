# v0.18.0 — workflow roles, adjustable parameters

Six workflow files become two, and a call can set the size.

## Added

- **Role sections** in the Workflows card: Text to image and Image to image,
  detected from the JSON (`{{image}}` marks an edit workflow) with a per-row
  override.
- **Per-role active workflow**: generation uses the active text workflow,
  `edit_image` uses the active edit workflow. The legacy single key still seeds
  the text slot, so existing configs keep working.
- **Numeric placeholders**: `{{width}}`, `{{height}}`, `{{steps}}`, `{{cfg}}`,
  injected as real numbers with bounds (64–8192, 1–150, 0–30).
- **Tool parameters**: `generate_image`, `generate_images` and `edit_image`
  accept `width`, `height`, `steps`, `cfg` when the chosen workflow declares
  them.
- **Studio**: size presets (Square 1024, Portrait 768×1344, Wide 1344×768) plus
  width/height fields, and a Sampling section for steps/cfg, shown only for
  workflows that expose them.
- **Import summary**: the card reports the detected role, capability chips and a
  warning when an existing workflow already covers the same role and size.
- `docs/comfyui-workflows.md` explains the placeholders and the conversion of a
  size-baked workflow into a templated one.

## Messages over guesses

A parameter the workflow bakes is an error that names the fix, not a silent
fallback; a declared placeholder without a value is an error too. Naming a
workflow from the wrong role explains which one the call needed.

## Migration

Nothing is rewritten. Roles are detected on load, the old active workflow keeps
driving generation, and a user who wants one Turbo workflow imports it with
`{{width}}`/`{{height}}` and removes the variants the summary flagged as
duplicates.
