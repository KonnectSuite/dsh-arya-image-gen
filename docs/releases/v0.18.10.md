# v0.18.10 — Arya Image gets a real tool list

The 0.18.9 notes ended with a limitation: an Arya Image session had the image
tools and nothing else, so reference hunting was impossible there. That is gone.

## What was wrong

The preset mounted three rows and relied on masking the inherited tools. A
restriction can only name what the host registers globally, so the mask kept the
eleven image tools, dropped every host tool as "unknown for this scope", and the
session started with no `read`, no `pwsh` and no `web_search`.

The shipped presets and the AryaCode presets do the opposite: they **declare the
rows** and mount no mask at all. Rows are the mechanism; masking was never one.

## Changed

The definition is now Arya Standard's row list minus skills, goals, plan mode
and delegation, plus the web rows:

```
persona, agent-instructions, time-context,
tool-bash / tool-pwsh (disabled by platform), tool-fs, tool-fs-search,
tool-jobs, tool-web { fetch: true, searchTimeoutMs: 60000 },
tool-ask-user, present
```

The mask row is removed, and with it the `ctx.tools.get()` presence filter that
caused the original loss.

## Verified on the dev profile

A fresh **Arya Image** session reports its tools:

```
ask_user_question, canvas_state, edit, edit_image, find_inspiration,
generate_image, generate_images, glob, grep, import_reference_image,
job_kill, job_list, job_output, list_render_templates, list_workflows,
present, pwsh, read, read_image, render_html, render_svg, view_canvas,
web_fetch, web_search, working_directory, write
```

So the reference loop from 0.18.9 — `web_search` → `web_fetch` →
`import_reference_image` → `edit_image` — now runs inside the image preset, not
only on Standard mode.
