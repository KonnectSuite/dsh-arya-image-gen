# v0.18.11 — any number of references, and a compose workflow

"Put this chair in my living room" needs two photographs at once. Until now the
plugin refused more than one source image, and no shipped workflow had a second
image input.

## The dynamic reference list

A workflow can now declare `{{images}}` instead of a single `{{image}}`:

```json
"images.image_1": ["{{images}}", 0]
```

For N supplied references the plugin drops that link, creates N `LoadImage`
nodes with fresh ids, and wires them to `images.image_1 … image_N` **in call
order** — so "image 1 is the subject, image 2 is the scene" holds.

- `edit_image(source_paths=[…])`, `source_image_ids` and inline attachments all
  feed it in order; Studio passes every uploaded reference instead of the first.
- The encoder's own ceiling applies: 16 slots.
- A workflow with a single `{{image}}` still takes exactly one, and now says so
  with the fix: "use a workflow that declares {{images}} for multi-reference
  composition".

## New workflow

`qwen-image-compose.json` — same Qwen Image 2.1 graph as the edit workflow, with
the encoder's image input made dynamic. Label in the picker: **Qwen Image 2.1 -
compose (any number of references)**. It is image-to-image by role, so
`list_workflows` reports it and an edit call can name it.

## Verified against the live server

`tests/live-compose.spec.ts` (opt-in, `COMFY_LIVE=1`) uploaded two real PNGs and
ran them through the compose workflow on the local ComfyUI: the run produced an
image in 16.5 s. Unit tests cover the expansion (order, ids, empty, 17 refused,
single-image workflow refusing extras, a marker on an unnumbered key).
