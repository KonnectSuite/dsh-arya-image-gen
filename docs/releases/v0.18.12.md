# v0.18.12 — ComfyUI is the default route, and its server controls fit how you run it

Two things: the agent no longer drifts to HTML/SVG on its own, and starting,
stopping and restarting ComfyUI from the card works with a scheduled task
instead of asking you to script it.

## ComfyUI first

The persona and the `arya-image-workflows` skill now say it plainly:

- `generate_image` / `generate_images` / `edit_image` are the route for every
  image request;
- `render_html` and `render_svg` are for pictures whose point is exact, legible
  text and layout, or when the user asks for them;
- when a ComfyUI call fails with a connection error, say the server looks down
  and offer **Settings → Plugins → Arya Image Gen → Server → Start** instead of
  quietly drawing it another way.

## Server control without a script

New **Launch method** setting, default **Automatic**:

| method | start | stop |
|---|---|---|
| Automatic | a scheduled task named below if it exists, else the Python route | matching `schtasks /end`, then the port backstop |
| Scheduled task | `schtasks /run /tn <name>` | `schtasks /end` + kill whatever still holds the port |
| Python process | spawn `main.py` with the configured interpreter | kill ComfyUI's own `main.py` process |

So a tray/service install like `C:\Users\KNPhu\ComfyUI-Service` needs **no
paths at all**: the card reads the task, shows `Auto: using scheduled task
"ComfyUI" (Running).`, and the Start / Stop / Restart buttons drive it.

Hardened while testing against that install:

- a task that still reads `Running` after a stop is ended before the next run
  (`schtasks /run` refuses otherwise);
- a process holding the port without answering is killed before launching, so a
  restart cannot fail to bind on a zombie;
- the start window is 180 s, and a timeout now reports the task state as well as
  the log tail.
