# v0.18.3 — the agent chooses the workflow

The composer pill is not the mechanism any more: the model can see the workflow
catalog and pick deliberately.

## Added

- **`list_workflows`** — every configured workflow with its role, which
  parameters a call may set, the size it bakes, and which one each role picks by
  default. This is what lets the agent name a cutout, a background removal or an
  adjustable-size workflow on purpose instead of inheriting the last active one.
- **`arya-image-workflows` skill** — how to match a request to a workflow, and
  the mistakes to avoid (naming a workflow from the other role, passing a size to
  a workflow that bakes it).

## Fixed

- An install with **no configured workflows** now falls back to the shipped pack
  instead of reporting "No workflow imported" forever. An old profile that saved
  an empty list (or was installed at 0.13.0, before the pack existed) starts
  working without an import step.

## Not changed

- Per-role auto-selection. `generate_image` still resolves the active
  text-to-image workflow and `edit_image` the active image-to-image one; the new
  tool only adds the *choice* on top of that default.
- The composer pill stays a human convenience, off by default
  (`showProviderPill`). It exists to pin a workflow without typing, not because
  the agent needs it.
