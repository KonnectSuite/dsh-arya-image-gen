# v0.18.5 — the composer pill is gone

The workflow switcher beside the chat input is deleted, not hidden. It was a
second place to pick a workflow and it duplicated the two that already work:

- the **settings card** lists every imported workflow per role and marks the
  active one, which is where a human changes it;
- **`list_workflows`** plus the `arya-image-workflows` skill let the model choose
  the right workflow from the request, which is how the agent was already
  working.

## Removed

- `src/client/provider-pill.tsx` and its stylesheet, plus the
  `conversation.input.right` slot registration in `src/client/index.tsx`.
- The `showProviderPill` setting: config field, schema entry and the
  **Interface** section of the settings card that held the toggle.
- The two `conversation.input.right` assertions in
  `tests/client-compat.spec.ts`, and the line in `docs/render-plan.md` that
  listed a renderer pill as deferred.

## Upgrade note

A profile that already carries `showProviderPill: true` keeps the key after the
upgrade. It is inert: the schema tolerates unknown keys, nothing reads it, and
the pill no longer exists to be shown. Edit the profile file to drop the line if
the stale key is unwanted; no reinstall step is needed.
