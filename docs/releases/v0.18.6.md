# v0.18.6 — the Arya Image preset actually registers

The preset never reached the host's registry, so the picker never listed it. The
plugin registered it by calling `ctx.inject(['agentPresets'], …)` from inside its
own `apply()`. That callback starts a plugin of its own *after* the entry has
already applied, so the registration can land after the Loader settles — and a
preset list the client has already read never gains the entry.

## Changed

The registration now uses the pattern the AryaCode presets use
(`dsh-aryacode-polish/presets/arya-standard/plugin.js`): a mount point of its own,
exported with `inject = ['agentPresets']`, mounted with `ctx.plugin()`. The Loader
holds that mount until the registry exists, so the definition is in place while
the composition is still settling. The service is read through `ctx.get()`, the
way the preset plugins read it, and a composition without the registry still
boots without it.

## Diagnosing it

The mount logs on entry:

```
arya-image-preset: mount point active
arya-image-preset: registered arya-image (Arya Image)
```

A boot log with the first line and not the second means the registry rejected the
definition and the reason is logged beside it. No line from this module at all
means the Loader never reached the mount, which points at the composition rather
than the preset.

## Unchanged

The definition itself — id `arya-image`, order 2.5, the image persona, the
tool-ask-user and present rows, and the tool mask that keeps the image tools plus
the core set.
