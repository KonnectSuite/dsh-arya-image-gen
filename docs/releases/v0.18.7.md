# v0.18.7 — Arya Image actually shows in the picker

Verified on the `dev` profile before publishing: the preset registers as
`arya-image` at order 2.5 and the composer's preset picker lists **Arya Image**
with its description. The registry's own listing reports it with no `broken`
field.

## What was still wrong in 0.18.6

Registration worked (0.18.6 mounted it the way the AryaCode presets do), but the
definition was reported broken:

```
arya-image-toolset (dsh-arya-image-gen/agent-toolset):
cannot get property "tools" without inject
```

A preset row runs in a scoped context where only declared services are visible,
and the Loader reads `inject` from the **module**, not from a property on the
exported `apply` function. The mask row therefore had no `ctx.tools`, failed to
activate, and the host marked the whole preset broken — which the client hides,
so the picker showed nothing at all.

## Changed

- `src/agent-preset/toolset.ts` declares `export const inject = ['tools']` (the
  function property stays for a direct `ctx.plugin()` mount).
- `src/agent-preset/register.ts` reads the registry's own list after registering
  and warns when the host reports this preset broken, so a row that fails to
  activate says so in the log instead of silently disappearing from the picker.
- `tests/agent-preset.spec.ts` pins the named `inject` export and the `tools`
  service declaration.
