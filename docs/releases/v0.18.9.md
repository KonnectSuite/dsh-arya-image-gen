# v0.18.9 — reference images from the web

An image model knows the *idea* of the Eiffel Tower, not this Eiffel Tower on
this site. For anything that already exists, a real photograph beats any
description, so the plugin can now fetch one, keep it in the workspace, and edit
from it.

## New

- **`import_reference_image`** — downloads one public image URL into
  `<workspace>/<folder>/references/` and returns the path `edit_image` takes as
  `source_path`. It is deliberately strict: http/https only, no credentials in
  the URL, every resolved address must be public (loopback, private, link-local
  and CGNAT refused, including after a redirect), at most four redirects, PNG /
  JPEG / WebP decided by magic bytes rather than `content-type`, a 16 MB cap
  enforced while streaming, and the file contained inside the workspace. Pixel
  dimensions come from the header, so the model can judge the reference before
  using it.
- **`arya-image-references` skill** — when a reference is worth it, how to
  search for one, how to tell a page from a file, how many to use, and the
  honesty and licensing rules.
- **Preset persona** gained the same rule in two sentences, so an `Arya Image`
  session knows to ask for a reference when it has no web tools.
- **Docs**: `docs/reference-images.md` — the loop, the guarantees table, source
  quality rules, failure messages and their meaning.

## Fixed while building it

The tool mask filtered its allow list with `ctx.tools.get(name)`, which answers
from the global view only. Once presets moved their tools onto the agent plane,
that lookup reported the host's own tools as absent, so the mask stripped them
and kept only the image tools. The mask now submits the full list and drops
exactly the names `restrict()` calls unknown, retrying once — the same outcome
on a lean host, without depending on a view that no longer answers.

## Verified on the dev profile

Standard-mode session, real network:

```
web_search → web_fetch (Wikimedia Commons page)
import_reference_image(url="…/1280px-Tour_Eiffel_Wikimedia_Commons.jpg", name="eiffel")
→ image/jpeg, 614,616 bytes, 1280 × 2369
→ …/dsh-arya-image-gen/references/eiffel.jpg
```

The file is on disk at that path and 614,616 bytes, matching the tool's reply.

## Known limitation — the Arya Image preset

A preset registered through the runtime API resolves this bundle's tools but not
the host's base tools (`read`, `pwsh`, `web_search`, …): the host supplies those
from the composition and `restrict()` reports them as unknown for that scope.
Those sessions therefore have the eleven image tools and nothing else, so
reference hunting happens on **Standard mode** / **Arya Standard**. The fix is
to declare the preset as a composition row (`preset-arya-image`,
`name: '@deepseek-ai/dsh-agent-preset'`) instead of registering it at runtime;
that is not in this release.
