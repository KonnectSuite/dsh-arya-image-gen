# v0.20.0 — the package takes the scoped name, and the documentation says what the plugin does

*Published to npm on 2026-11-22. Two packaging faults in this archive were fixed the same day by [0.20.1](v0.20.1.md): the icon the manifest advertises was not packed, and 18 MB of README screenshots were.*

## Why the name changed

The first-party naming rule for AryaCode's public plugins is `@aryacode/dsh-<name>`. Two of the three public plugins already follow it — `@aryacode/dsh-plugin-arya-computer-use` and `@aryacode/dsh-engineering` — and this one did not, so its install line, its catalogue entry and its tarball named three different things depending on where you looked. A user comparing the npm page, the market page and the README could not tell they were the same plugin.

The scoped name is the one the documentation leads with, so the docs, the manifest, the bundle id and the catalogue agree from here on.

## What moves, and what does not

**Moves** (all in the same commit as the bump):

| Touchpoint | Change |
|---|---|
| `package.json:2` | `name` → `@aryacode/dsh-arya-image-gen` |
| `cordis.patch.yml:3` | the layer's `name` → scoped |
| `tsdown.config.ts:12/14/29/52` | bundle `name`s and the `window.__ModuleLoader__.load({ id: … })` banner → scoped |
| `src/agent-preset/definition.ts:49` | `ARYA_IMAGE_TOOLSET_MODULE` → `@aryacode/dsh-arya-image-gen/agent-toolset` |
| `tests/agent-preset.spec.ts:65` | the expected row module → scoped |
| `scripts/check-package.mjs:37/52` | the temp install's dependency key and the resolved `node_modules` path → scoped |
| `scripts/fixtures/package-settings.mjs:16/27` | `import.meta.resolve` and the dynamic `import()` → scoped |
| seven `@module` doc tags | rewritten to the scoped subpath |

The repository URL stays `github.com/KonnectSuite/dsh-arya-image-gen`: a scope renames the package, not the repository.

**Does not move**, because it is derived from the plugin's registered name, not its package name:

| Identity | Where it lives |
|---|---|
| plugin id `dsh-image-gen` | `src/index.ts:43` (`export const name`) |
| settings namespace `image-gen` | the DSH settings service, keyed off that id |
| every route `/plugins/dsh-image-gen/*` | `src/shared.ts:6-39` |
| workspace folder for saved images `dsh-arya-image-gen` | `src/config.ts:38` (`DEFAULT_WORKSPACE_FOLDER`) |
| inspiration cache `~/.dsh/cache/dsh-image-gen/inspiration/` | `src/inspiration-route.ts:220` |
| the tool names, the attachment `kind` values, the IndexedDB names | unchanged |

So the upgrade is: remove the old package, add the new one, restart the profile. Settings, imported workflows, gallery and saved images are the same rows on disk. The two packages must not be mounted at once — same id, two layers.

## What the release step has to do

The scoped package does not exist on npm until the release step runs, from the owner's machine, with npm authentication:

```
node ../dsh-arya-market/scripts/release-plugin.mjs --dir ../dsh-arya-image-gen
```

That publishes the tarball, regenerates and commits `index.json`, tags the commit, pushes, and then proves four conditions: npm serves the version, the market `catalog` branch lists it, the entry's `releases[0].sha256` is the hash npm serves, and `check-catalogue-parity.mjs` exits 0. Alongside it, the old name is deprecated in place — never unpublished:

```
npm deprecate dsh-arya-image-gen "renamed to @aryacode/dsh-arya-image-gen"
```

Until then the README says plainly that 0.19.2 is the newest release on npm and that it lives under the old name, and the root `index.json` lists the versions under the name npm actually serves. `scripts/sync-market-index.mjs` flips the listing's entry to the scoped name on the release run, because it reads the name out of `package.json`.

**This has happened.** 0.20.0 and 0.20.1 are on npm under `@aryacode/dsh-arya-image-gen`, the root listing carries the scoped entry, and the old name is deprecated in place rather than pulled down, so `npm view dsh-arya-image-gen` still resolves and tells you where the package went.

## The documentation overhaul that came with it

The plugin's public pages had drifted from the plugin. The set was rebuilt against the code and against the public-plugin reading order in the market repository's `AGENTS-PLUGINS.md`:

- **`README.md`** — rewritten: requirements before install, four install routes with the real host UI paths, where the plugin appears in the interface, first-run steps, a settings table covering every field in `src/config.ts`, the remove path including every trace it leaves, and a troubleshooting table built from failures users actually hit. It is written for a DeepSeek Harness web profile; AryaCode is named as a rebranded DSH build so the same package and the same routes apply to both.
- **`CHANGELOG.md`** — new, 28 versions, dated from the npm packument, condensed from `docs/releases/`. It is the input to the release tooling, not a courtesy file.
- **`SECURITY.md`** — rewritten. The old one described API keys for providers this plugin removed.
- **`CONTRIBUTING.md`** — rewritten. The old one sent contributors to edit files that no longer exist.
- **`docs/index.md`** — new: the documentation mapped by task.
- **`index.json` + `scripts/sync-market-index.mjs`** — the self-registered index listing, moved to the repository root where jsDelivr serves it and the release step commits it, with a script so it cannot drift again.
- **`icon.svg`**, **`.github/ISSUE_TEMPLATE/*`**, **`.github/PULL_REQUEST_TEMPLATE.md`**, **`.github/workflows/release.yml`**, **`HANDOFF.md`**.
- Fixed: `docs/comfyui-workflows.md` claimed four shipped workflows; there are five. `docs/install-comfyui.md` credited the plugin with a `comfy-mcp` engine it does not have. Deleted: `docs/arya-catalog.workflow.yml`, `scripts/upsert-arya-catalog.mjs`, `docs/market/index.json`, the zero-byte `Connection` file.

## Known gaps at this commit

- Documentation is English-only; the sibling public plugins ship `README.zh.md`.
- `scripts/fixtures/package-settings.mjs` asserted the removed multi-provider settings card (`Default model`, `Editing model`, `googleNative`, `openaiCompatEditFormat`), so `pnpm run test:package` failed. It was rewritten against the ComfyUI card in this same release: it boots the packed, renamed tarball inside a real DSH settings host and asserts both schemastery branches, 3.18.4 and 3.18.2.
- No git tag exists for 0.19.2 or for anything before 0.19.1, so GitHub Releases start with this version.
- The repository's GitHub About text still points at the upstream project, and Issues are disabled — both are settings, not files.
