# v0.20.1 — the archive ships what the manifest advertises

Two faults in the 0.20.0 tarball, both found by reading the published archive
rather than the source tree: the icon the manifest promises was not in it, and
18 MB of README screenshots were.

## Packaging

- **`icon.svg` is now in `files`.** `package.json` maps
  `exports["./icon"] → ./icon.svg`, and `icon.svg` exists in the repository, but
  `files` did not list it, so the 0.20.0 archive resolved that subpath to nothing.
  The sibling public plugin `@aryacode/dsh-plugin-arya-computer-use` ships its
  mark the same way, so the family is consistent again.
- **`docs/assets/readme/*.webp` is out of `files`.** Those are the README and
  documentation pictures — 20 of them, 18 MB — and they exist to be rendered by
  GitHub and jsDelivr from the repository, not to be installed. Nothing at
  runtime reads `docs/`: the prefill workflow pack is compiled into
  `src/generated/default-workflows.ts` by `pnpm run sync:workflows`, which is why
  `docs/workflows/*.json` stay in the archive as the importable copies. The
  installed package went from 20 MB over 104 files to 1.7 MB over 84 files.
- `docs/workflows/*` (five JSON graphs plus the zip), `skills/**/*.md`,
  `lib/index.js`, `lib/client.js`, `lib/agent-toolset.js`, `lib/types/**/*.d.ts`,
  `cordis.patch.yml`, `README.md`, `LICENSE` and `NOTICE` are unchanged in the
  archive.

## The index listing follows the rename

`scripts/sync-market-index.mjs` keys the listing off `package.json`, so
`index.json` now carries one entry named `@aryacode/dsh-arya-image-gen` and
lists the versions npm serves under that name — 0.20.0 upward. The pre-rename
versions (0.11.0–0.19.2) are not under it and never will be: they were published
under the unscoped name, and the generator refuses to list versions the registry
does not serve. Those releases stay installable by their own name, which is
deprecated in place rather than pulled down.

## Verified

`pnpm run typecheck`, `pnpm test` (422 passed, 1 skipped), `pnpm run build`,
`pnpm run pack:check`. `pnpm run test:package` — which packs this tree, installs
the tarball into a throwaway package against published DSH services and boots it
through a real settings host — passes both schemastery branches: 3.18.4 persists
every field through a fresh form and a host restart, 3.18.2 reports the failure
in the card and writes nothing.
