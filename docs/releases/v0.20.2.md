# v0.20.2 — the archive carries the instructions it wants you to follow

0.20.1 fixed what was inside the tarball. This fixes what the tarball *says*.
Nothing under `lib/` differs between 0.20.1 and 0.20.2 except the version
string, and the settings, routes, tools and canvas are the same build.

## The README inside the tarball

- `README.md` is in `files`, and npm renders a package page from the copy inside
  the tarball — not from the repository. So the page for
  `@aryacode/dsh-arya-image-gen` was showing whatever README happened to be
  packed at publish time.
- 0.20.0 and 0.20.1 were packed before the documentation rewrite landed, so that
  page still read `dsh plugin --profile web add dsh-arya-image-gen` and pointed
  its npm badge at the unscoped name.
- That install line now installs a deprecated package: the old name carries a
  deprecation notice on every version it serves (`npm view
  dsh-arya-image-gen@0.19.2 deprecated`), and no 0.20.x was ever published under
  it. A reader following the page would land on 0.19.2 believing it was current.
- 0.20.2 is the same code with the README that tells the truth: the scoped
  install line, the scoped badge, and the paragraph explaining that the rename
  moved the package, not the plugin — the plugin id stays `dsh-image-gen`, so
  endpoint, workflows, gallery and saved images come across when you remove the
  old package and add the new one.

## The index generator was reading the wrong document

- `scripts/sync-market-index.mjs` read the packument with
  `npm view <name> --json`, which looks like the packument and is not one: the
  CLI answers with an array-wrapped abbreviated summary whose `versions` is a
  flat list of version strings and whose per-version manifests are dropped.
- Iterating that yields array indexes, so the publish-time lookup missed on the
  first one and the script exited with
  `npm has no publish time for @aryacode/dsh-arya-image-gen@0`. The release step
  reported it as a stopped GitHub step and skipped the tag, the release and the
  listing — the exact silent drift this script was written to prevent.
- Even had it continued, the other thing the listing needs — the `engines.dsh`
  range each version declared — is not in that document at all.
- It fetches `https://registry.npmjs.org/<name>` over HTTPS now. The scoped name
  keeps its slash; the registry routes `@scope/name` directly. The guard rejects
  an abbreviated answer rather than mis-listing from it.
- `index.json` regenerated against the real packument: one entry
  `@aryacode/dsh-arya-image-gen`, two versions, publish times 1795310393 and
  1795310617, `engines.dsh` `>=0.1.7 <1` on both. The pre-rename releases are
  not under this name — they stay installable by it, deprecated in place.

## Verified

`pnpm run typecheck`, `pnpm test` (422 passed, 1 skipped), `pnpm run build`,
`pnpm run pack:check`, and `pnpm run test:package` — the fixture that installs
the packed tarball into a throwaway package and boots it through a real DSH
settings host — passing both schemastery branches. The release step then packs
this tree, records the sha256 the registry actually serves, and reconciles the
market catalogue against it.
